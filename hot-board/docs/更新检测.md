# 软件更新检测

设置面板里的「软件更新」：打开设置时自动检查一次，启动时也会静默检查一次（有新版本就在齿轮按钮上点个红点）。检查只比对版本号，下载交给系统浏览器。

## 版本号从哪来

当前版本取自 `src-tauri/tauri.conf.json` 的 `version`，编译时写进程序。发版前记得三处一起改：

- `src-tauri/tauri.conf.json`
- `src-tauri/Cargo.toml`
- `package.json`（以及 `package-lock.json` 顶部的两处）

## 云端清单

地址写在 `src-tauri/update_config.url`，只认第一条 http(s) 地址，`#` 开头是注释。默认：

`https://sport.tomist.com/hot-board/latest.json`

这个地址是编译进程序的，改地址要重新打包；只改清单内容不用。

清单最小内容只要 `version`：

```json
{
  "version": "0.1.4",
  "url": "https://sport.tomist.com/hot-board/非凡热点榜_0.1.4_x64-setup.exe",
  "notes": "1. 卡片改为分页\n2. 工具栏统一图标",
  "publishedAt": "2026-10-20"
}
```

`url` 直接用安装包的原文件名即可，中文名浏览器会自动转义（`非凡热点榜_0.1.2_x64-setup.exe` 实测能正常下载）。服务器上的目录结构：

```
/www/wwwroot/sport.tomist.com/public/hot-board/
├── boards.json                          # 榜单清单
├── latest.json                          # 更新清单
└── 非凡热点榜_0.1.4_x64-setup.exe        # 安装包
```

| 字段 | 必填 | 用途 |
|---|---|---|
| `version` | 是 | 和本地版本比大小 |
| `url` | 否 | 安装包直链，「下载更新」用浏览器打开 |
| `pageUrl` | 否 | 没有直链时给一个下载页 |
| `notes` | 否 | 更新说明，字符串或字符串数组都行（数组按行拼接） |
| `publishedAt` | 否 | 纯展示 |

清单里两个地址都没有时，界面提示「更新清单里没有下载地址」，不显示下载按钮。

## 版本比较规则

按点分数字逐段比较，`v` 前缀、`-` / `+` 后面的预发布后缀忽略。所以 `0.1.10` 比 `0.1.9` 新，`v0.1.3` 和 `0.1.3` 相同，`0.1` 和 `0.1.0` 相同。

## 网络

检查请求走设置里的代理：全局「完全关闭」时直连；「手动指定」用手填的代理；「跟随系统代理」在检测到系统代理时走代理，否则直连。更新检查不参与「每个源的开关」。

## 发版流程

1. 三处版本号加一位，重新 `tauri build`。
2. 把新安装包传到 `public/hot-board/` 下。
3. 改云端 `latest.json` 的 `version`、`url`、`notes`，保存即生效。

已经装出去的旧版本只要清单地址没变，下次打开就能看到红点。装之前先退出软件（包括托盘），否则 NSIS 盖不掉正在用的 exe。

> 清单地址是编译进程序的。2026-10-18 把榜单清单从 `/boards.json` 挪到了 `/hot-board/boards.json`，旧路径已 404；0.1.2 及更早的客户端只会用缓存。如果还想照顾它们，可以在站点根目录留一份同样的 `boards.json`。

## 没做的事

- 没有用 Tauri 官方 updater 插件，因此没有签名校验，也不能在应用内静默下载、自动覆盖安装。
- 没有强制更新，用户点「稍后」就不再提示，除非他自己点「重新检查」。
