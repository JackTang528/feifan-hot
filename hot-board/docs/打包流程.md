# 非凡热点榜打包流程

给接手的人：按下面做就能打出当前用户安装包。产品名「非凡热点榜」，版本在 `src-tauri/tauri.conf.json` 的 `version`。

最近一次成功产物（2026-10-13，版本 0.1.0）：

`src-tauri/target/release/bundle/nsis/非凡热点榜_0.1.0_x64-setup.exe`（约 3.2 MB）

## 环境

- Windows 10/11
- Node.js 20+
- Rust stable（rustup）
- Visual Studio「使用 C++ 的桌面开发」（含 MSVC、Windows SDK）
- WebView2：安装包不内置运行库，用户机器没有时会静默下载引导程序

在 `hot-board` 目录执行过一次 `npm install` 即可，不必每次重装依赖。

## 打包命令

在 `hot-board` 目录：

```powershell
$env:CARGO_TARGET_DIR = "$PWD\src-tauri\target"
npx tauri build --bundles nsis
```

`CARGO_TARGET_DIR` 要指到项目里的 `src-tauri\target`。Cursor 沙箱有时会把它指到临时目录，不改的话打包器会去错误路径找 `hot-board.exe`，报「系统找不到指定的路径」。

这条命令会先跑 `npm run build`（`tsc` + Vite），再编译 Rust release，最后用 NSIS 打安装包。源码没大改时，Rust 增量编译大约两三分钟。

只改了图标或 NSIS 配置、程序本身不用重编时，可以：

```powershell
$env:CARGO_TARGET_DIR = "$PWD\src-tauri\target"
npx tauri bundle --bundles nsis
```

前提是 `src-tauri\target\release\hot-board.exe` 已经存在。榜单逻辑、前端文案变了必须用上面的 `tauri build`。

## 安装包行为

配置在 `src-tauri/tauri.conf.json`：

- 只打 NSIS，不打 MSI
- `installMode` 为 `currentUser`，装到当前用户，不要求管理员
- 语言：简体中文、英文
- 安装程序图标和软件图标都是 `src-tauri/icons/installer.ico`
- WebView2 使用 `downloadBootstrapper`，静默

安装前先退出正在运行的「非凡热点榜」，否则安装包可能盖不掉正在用的 exe。

## 图标

正确图标是白底青黄标志，文件只有：

- `src-tauri/icons/installer.ico`
- `src-tauri/icons/installer.png`

深色底、带「非凡热点榜」字的那套已经删掉，不要再生成回来。

`installer.ico` 必须是不透明白底。透明底进 NSIS 后，透明区域会变成黑底。多尺寸用传统 BMP 图标（16、24、32、48、64、128、256），不要只用 PNG 压缩的 ico。

## 云端榜单和打包的关系

刷新时先请求 `src-tauri/board_config.url` 里那一行地址。当前是：

`https://sport.tomist.com/hot-board/boards.json`

服务器上的实际文件在 `/www/wwwroot/sport.tomist.com/public/hot-board/`，和安装包、`latest.json` 放在一起。

这份 JSON 的字段说明和一份同样内容的内置副本在 `src-tauri/boards.json`。云端失败时，用上次成功拉下的清单；还没有的话用内置副本。上次成功的清单位于：

`%APPDATA%\com.tauri-app.hot-board\board_catalog.json`

| 要改的东西 | 要不要重新打包 |
|---|---|
| 加减 RSS 榜、改名、改顺序、改 RSS 地址 | 不用。改服务器上的 `boards.json`，用户点「全部刷新」 |
| 云端地址本身 | 要。改 `src-tauri/board_config.url` 后再 `tauri build`。这个地址是编译进程序的 |
| 微博、B站、头条、HN 的抓取代码 | 要。这些是 `kind: "builtin"`，解析写在 Rust 里 |
| 新的非 RSS 站点 | 要。先写适配器，再在 `src-tauri/src/catalog.rs` 的 `builtin()` 里登记 |
| 图标 | 要 |

已经装在用户机器上的旧版本不会读云端清单。必须先装上包含 `board_config.url` 的这一版，之后改 JSON 才对用户生效。

## 本地开发

```powershell
cd hot-board
npm run tauri dev
```

第一次会编译 Rust，比打包更久。界面改动 Vite 会热更新；Rust 改动需要重启 `tauri dev`。

单测（解析 RSS、内置清单）：

```powershell
$env:CARGO_TARGET_DIR = "$PWD\src-tauri\target"
cargo test --lib -j 2
```

并行度太高时，本机 rustc 可能直接崩溃（退出码 `0xc0000409`）。那不是代码错误，把 `-j` 降到 2 再跑。

## 发布前检查

1. `tauri.conf.json` 的 `version` 是否要升。安装包文件名带这个版本号。
2. `board_config.url` 是否仍是 `https://sport.tomist.com/hot-board/boards.json`，且浏览器能打开、内容是 `{"boards":[...]}`。
3. 安装后打开软件，点「全部刷新」，六个榜都出现：Hacker News、微博热搜、B站热门、今日头条热榜、Google 趋势、Google 新闻。
4. 安装包图标和软件图标都是白底标志，不是黑底。

当前没有代码签名。安装时 Windows SmartScreen 可能提示未知发布者。
